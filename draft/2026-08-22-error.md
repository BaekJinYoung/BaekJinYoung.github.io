### [Troubleshooting] Windows Git Bash에서 Laravel 설치 중 Exec format error 및 Scoop을 통한 환경 구축 해결기

#### 1. 문제 상황 (Issue)

Windows 환경의 Git Bash에서 Laravel 개발 환경 구축을 위해 스크립트를 실행하고 PHP 바이너리를 호출하려 했으나 아래와 같은 실행 오류가 발생하며 진행이 중단되었다.

```bash
/c/Users/JIN/.config/herd-lite/bin/php: cannot execute binary file: Exec format error

```

단순히 PATH 환경 변수가 등록되지 않은 문제로 보였으나, 경로 설정만으로는 해결되지 않는 바이너리 자체의 실행 문제가 발생했다.

---

#### 2. 원인 추적 (Debugging)

**1) 바이너리 파일 포맷 검증**
Git Bash에서 `file` 명령어로 에러가 발생한 PHP 파일의 형식을 확인했다.

```bash
$ file ~/.config/herd-lite/bin/php
/c/Users/JIN/.config/herd-lite/bin/php: ELF 64-bit LSB executable, x86-64, version 1 (SYSV), statically linked, stripped

```

**2) 원인 분석**

* **결과 검증:** 확인된 `php` 파일은 Windows용 Executable(`.exe`)이 아니라 Linux OS용 실행 파일 형식인 **`ELF 64-bit`** 바이너리였다.
* **설치 명령 확인:** 초기 설치 시 사용했던 스크립트 URL에 `/install/linux/8.5`가 명시되어 있었고, 이로 인해 Windows 환경임에도 Linux OS 전용 바이너리가 다운로드되었음을 확인했다.
* **결론:** Windows 호스트 환경(MINGW64/Git Bash)에서 Linux 전용 ELF 바이너리를 직접 실행하려 했기 때문에 OS 차원에서 `Exec format error`가 발생한 것이다.

---

#### 3. 해결 과정 (Solution)

GUI 기반 인스톨러(Herd) 설치 과정에서 앱 실행 및 종속성 문제가 이어졌기 때문에, Windows 패키지 매니저인 **Scoop**을 통해 CLI 환경에서 Windows 네이티브 PHP 및 Composer를 구축하는 방식을 선택했다.

**1단계: 기존 Linux 바이너리 잔재 삭제**
잘못 다운로드된 ELF 파일 및 설정 디렉터리를 정리했다.

```bash
rm -rf ~/.config/herd-lite
hash -r

```

**2단계: Scoop을 이용한 Windows용 PHP & Composer 설치**
Windows PowerShell 환경을 통해 Scoop 패키지 매니저로 Windows 네이티브 x64 PHP와 Composer를 설치했다.

```bash
# Scoop 기반 PHP & Composer 설치
powershell -Command "C:\Users\JIN\scoop\apps\scoop\current\bin\scoop.ps1 install php composer"

```

**3단계: Git Bash PATH 설정**
Scoop으로 설치된 바이너리 shims 경로와 Composer 글로벌 명령 경로를 `.bashrc`에 등록했다.

```bash
echo 'export PATH="$HOME/scoop/shims:$HOME/AppData/Roaming/Composer/vendor/bin:$PATH"' >> ~/.bashrc
source ~/.bashrc

```

**4단계: Laravel Installer 설치 및 최종 검증**
글로벌 패키지로 Laravel Installer를 설치하고 바이너리 동작을 검증했다.

```bash
# Windows 네이티브 PHP 버전 확인
$ php -v
PHP 8.5.9 (cli) (built: ...) # Exec format error 없이 정상 출력

# Composer & Laravel CLI 정상 인식 확인
$ composer --version
$ composer global require laravel/installer
$ laravel --version

```

---

#### 4. 배운 점 (Retrospective)

* **`Exec format error`의 본질:** 이 에러는 OS나 CPU 아키텍처(Windows vs Linux, x86 vs ARM)가 서로 맞지 않는 바이너리를 실행하려 할 때 발생하는 바이너리 수준의 오류임을 명확히 이해했다.
* **`file` 명령어의 활용:** 설치나 실행 에러가 발생했을 때 단순히 설치 과정을 반복하기보다, `file` 명령어로 대상 파일의 형식(ELF vs PE/Exe)을 먼저 확인하면 원인을 신속하게 추적할 수 있음을 배웠다.
* **개발 환경 복구 역량:** GUI 툴 설치가 난항을 겪을 때 패키지 매니저(Scoop)를 활용하여 CLI 기반으로 우회 구축하는 유연한 대응 방안을 익혔다.
